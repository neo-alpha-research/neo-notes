1. 강의 요지 (녹취 기반 정리본 기준)

단순 검색을 넘어 지식이 축적되는 회사 만들기

1) RAG vs LLM Wiki (단순 검색을 넘어선 축적형 지식 체계)

단순 검색형 RAG(Retrieval-Augmented Generation)는 질문할 때마다 파편화된 조각을 매번 찾아오는 '구글 검색' 방식으로, 질문이 끝나면 맥락이 사라지는 '금붕어 기억'의 한계가 있습니다. 반면 LLM Wiki는 새로운 정보(회의록, 고객 피드백)가 유입될 때 수석 사서처럼 기존 문서들을 읽고 자연스럽게 통합·수정·축적(Compounding Artifact)하는 살아있는 백과사전 모델입니다. 지식은 LLM Wiki 형태로 폴더에 컴파일하고, 실시간 질의는 그 위에서 RAG로 조회하는 결합 구조가 가장 안정적입니다.

2) 옵시디언(Obsidian)과 LLM의 역할 분담

안드레이 카파시(Andrej Karpathy)의 명제:
"옵시디언은 IDE(개발환경)이고, LLM은 프로그래머(개발자)이며, 위키(마크다운 문서들)는 코드베이스(소스코드)이다."

마크다운 문서가 수백~수천 개로 늘어나면 사람이 머리로 다 기억할 수 없습니다. 옵시디언의 폴더 구조와 지식 그래프를 통해 시각적으로 통제해야 합니다. Y Combinator CEO 게리 탄(Gary Tan)은 "잘 정리된 마크다운 문서 하나가 우리 회사의 직원 한 명이다 (A markdown file is an employee)"라고 강조했습니다.

3) 충돌 감지와 사람의 최종 중재 (Human-in-the-Loop)

회사가 성장하고 문서가 쌓이면 과거 가격(35,000원)과 신규 가격(50,000원)처럼 규칙 간의 충돌(Conflict)이 필연적으로 발생합니다. AI는 충돌을 감지해 태그([CHECK], [CONFLICT])를 붙여줄 수 있지만, "어느 것이 우리 회사의 진짜 표준인가"를 확정(Arbitration)하는 것은 오직 대표자(사람)의 몫입니다. 판정된 결정은 즉시 마크다운 규칙(Rule) 문서로 코드화해야 합니다.

4) 지식 린트 (Knowledge Lint: 보풀 제거와 규칙 정제)

지식 린트(Lint)의 본질:
스웨터의 보풀(Lint)을 떼어내듯, 낡고 엉킨 사문화된 규칙을 정기적으로 솎아내는 작업입니다. 파일이 늘어날수록 낡은 지침이 AI의 할루시네이션(환각)을 증폭시키므로, 주기적인 클린업 루틴이 필수적입니다.

5) 예의 바르고 완전한 문장의 프롬프트

AI를 단순 심부름꾼이 아니라 회사의 '고위 임원이나 전문 멘토'로 대우하며 정중하고 논리적인 완전한 문장으로 질문해야 합니다. 질문자가 생각을 가다듬어 완전한 문장을 쓰는 과정에서 스스로의 사고가 먼저 정돈되며, AI 또한 최상급의 분석 결과를 도출합니다.

핵심 관점 대조

RAG와 LLM Wiki의 핵심 차이

비교 항목 RAG (단순 검색 증강) LLM Wiki (축적형 백과사전)
작동 비유 구글 검색 (질문마다 파편 검색) 수석 사서의 백과사전 편찬 (누적 갱신)
기억 형태 단편적 청크 인출 (금붕어 기억) 유기적으로 연결된 살아있는 문서 체계
지식 축적 질문 시점에 일회성 조합 후 소멸 새 정보 유입 시 기존 문서에 자동 반영·축적
역할 분담 AI가 검색 결과 요약 Obsidian(IDE) - LLM(개발자) - Wiki(코드)
충돌 해결 검색 유사도 상위 문서 인용 충돌 감지 ➔ 대표자가 최종 기준 판정
유지 관리 임베딩 벡터 재계산 위주 지식 린트(Lint): 보풀 제거, 낡은 규칙 정리
2. 수강생 실천 기록 (내 업무 적용)

제가 실제로 해본 과정

강의에서 배운 방식을 제 실제 업무에 대입해 보며 실천한 4가지 과정입니다.

1) 기록을 로컬 폴더에 체계적으로 적재하기 (Lv.1 적용):
회의와 강연 메모, 외부 학습 기록을 마크다운 파일(.md)로 로컬 폴더에 먼저 쌓기 시작했습니다.

2) 일하는 기준(SOP) 문서화로 에이전트 연결하기 (Lv.2 적용):
'수치 인용 원칙', '금지 표현', '결과물 서식'을 담은 한 페이지짜리 기준 문서를 작성해 에이전트들이 읽고 협업하도록 구성했습니다.

3) 충돌 발생 시 대표자의 최종 판정 및 표준화:
정책 충돌이나 모호한 기준이 생겼을 때 AI에게 판단을 미루지 않고, 사람이 직접 최종 표준을 정해 공식 규칙 파일에 즉시 반영했습니다.

4) 정기적인 '지식 린트' 루틴 가동:
주간 점검 루틴을 두어 사문화된 규칙이나 낡은 메모를 솎아내고(보풀 제거), 지식 베이스의 무결성을 지속적으로 유지하고 있습니다.

(※ 녹음 요약 시 Gemini 활용은 수강생 개인이 편의를 위해 선택한 방식입니다.)
